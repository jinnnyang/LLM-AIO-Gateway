## 1. 组织者实测（评审基石，已抓真实 JSON 验证）

设计稿对数据源的假设与实际不符，三个源的价格表示、模态字段位置与词汇均不同：

| 维度 | models.dev | OpenRouter | LiteLLM |
|------|-----------|-----------|---------|
| 价格单位 | `cost:{input:2.5,output:10,cache_read:1.25}` **已是 $/M** | `pricing:{prompt:"0.0000025",...}` **per-token 字符串 ×1e6** | `input_cost_per_token:2.5e-06` **per-token 浮点** |
| 上下文位置 | `limit:{context,output}`（非顶层 `context`） | `context_length` 顶层 | `max_input_tokens` |
| 模态位置 | `modalities:{input:[text,image,pdf],output:[text]}` | `architecture.input_modalities`（顶层 `modalities` 为 null） | 仅 `supports_vision` bool |
| 模态词汇 | `pdf`/`image` | `image`/`file` | 无列表 |

**核心结论**：统一 `$/M token` 只是目标，落地必须为每源写独立适配器，不能共用同一字段名解析逻辑。

## 2. 🔴 必改项（8 条）

### 价格
1. **单位归一化必须按字段名分支**，不能一律 ×1e6。规则：`per_token→×1e6`、`per_1k→×1e3`、models.dev 已 $/M **勿二次换算**、OpenRouter 字符串先 `float()`。缓存价字段名三源各不同（`cache_read` / `input_cache_read` / LiteLLM cached），需分别兼容，缺失置 NULL。
2. **中位数策略升级**：先归一化单位 → 再按完整度分级（只对含 input+output 双价的源参与合并）→ cached 独立取中且允许缺省 → 单源直接采用并标注来源 → 候选仅一源且偏离 >10x 时标记人工复核而非静默采纳。原始"直接取中位数"在候选不可比时会掩盖异常。

### 模态
3. **模态并集改为"白名单宁漏勿虚"**（与原稿"保守多报"方向相反）。跨源词汇不统一（`image↔vision`、`pdf`/`file`），直接并集会失效且把单模型标成四模态全能。改：先按源官方 capability 字段白名单过滤，未声明的模态一律不加入；做 `image↔vision`、`pdf/file` 归类映射；output_modalities 用 `mode='chat'/'embedding'` 推断兜底。**宁可漏报（可回退），不虚报（错路由）**。

### DB
4. **价格列必须 `REAL` 允许 NULL**（绝不能 `NOT NULL DEFAULT 0`），否则无法区分"未采集"与"真为 0"，中位数与计费失真。`context_length/max_tokens` 用 `INTEGER` NULL。
5. **`metadata_sources` 一并加**（`TEXT NOT NULL DEFAULT '[]'`），否则 sync 后无法回查来源。建议加 `status` 字段区分"真无价格" vs "源解析失败"。

### 后端/API
6. **admin 全量回写不要扩 7 字段**。现有 `update_provider`（database.py:1493）只写 `model_name/enabled/preprocessor/image_generation`，把能力字段塞进 models 数组会让每次 saveModelEdit 洗掉手动值。能力字段走**独立端点**，且仅当 `source=='manual'` 才写（与 database.py:1510 现有守卫一致），auto 行拒绝。
7. **sync API 默认返回候选值不写库，显式 `?apply=true` 才写**。GET 幂等、可预览、规避与 refresh 的并发写冲突；响应同时返回候选值与"将被覆盖的现有值"供前端 diff；必须 `require_admin_session`。

### 安全
8. **XSS（本设计最大安全风险）**：sync 回填的候选值来自外部源，回填进 innerHTML 前必须 HTML 转义。测试需含恶意值回填用例。

## 3. 🟡 建议项

- **discovery 批量预取**：`refresh_all_providers` 已有 `asyncio.Semaphore(4)`，但几百模型逐模型 await 会卡单连接。在 for 循环外用 `asyncio.gather` 批量预取候选能力再一次性写入；UPDATE/INSERT 分支都写能力字段；单模型 resolve 异常 `try/except` 继续并保留旧值标记 `pending`（当前外层 try 粒度太粗会整体回滚）；manual/auto 同 id 时能力字段受同一 `source=='auto'` 守卫。
- **缓存**：进程内 dict + 锁，TTL 5-10min，键 `(provider_id, model_id)`，写库成功后**主动失效**对应键（DB 变化是唯一失效源）。单进程无碍，多 worker 需标注限制。
- **前端**：引入最小状态对象 `metadataState` + `readMetaForm()/writeMetaForm()` 两个纯函数；chips 用容器级事件委托（防重渲染丢焦点）；同步回填默认"只填空"，填充字段加"候选"视觉徽章，保存前一次性确认。
- **列表标签**：只显示价格（千分位）+ context 缩写（8K/128K），做成全局 localStorage 开关而非逐行。
- **i18n**：新文案（能力参数/同步/候选）须同时进 app.js:393（中）与 766（英），原稿未提。
- **里程碑**：顺序合理，但 M4 前后端拆两个子步；M1 补"向后兼容"验收（存量 auto 模型无 metadata 不崩）。

## 4. 开放问题定案建议

| 开放问题 | 定案 |
|---------|------|
| 1. 网络请求频率/缓存 | models.dev + OpenRouter 全量 JSON TTL 24h 缓存（内存 + 落表），变化低频；供应商 /models 每次 5s 超时静默降级 |
| 2. LiteLLM 单位系数 | **已实测解决**：per_token×1e6、per_1k×1e3、按字段名分支 |
| 3. 模态并集 | 白名单过滤 + 词汇映射，**方向反转为"宁漏勿虚"** |
| 4. 供应商 /models 是否纳入 | 建议纳入（auto 可选增强），仅作补充源、白名单过滤 |

## 5. 组织者综合判定

设计稿约 80% 可直接落地，三处需**实现前改设计决策**（非实现细节）：

1. **模态并集策略方向**（原 §2.3）——从"保守多报"改为"白名单宁漏勿虚"。
2. **admin 更新路径**（原 §4.4）——从"扩展现有 update 端点"改为"独立端点 + manual-only 守卫"。
3. **中位数规则**（原 §2.1/§8）——从"直接取中位数"改为"归一化 + 完整度分级 + 异常标记"。
