# docs

| 目录 | 内容 |
|---|---|
| [plans/](plans/) | 开发规划、设计方案、评审往来。记录当时的判断，不随实现漂移回写 |
| [issues/](issues/) | 开发中发现但不属当次任务主线的问题。含状态与「不建议做的事」 |
| [live-eval.md](live-eval.md) | 运行手册：`tools/live_eval/live_eval.py` 对已部署实例发真实请求。**会花费 token**，故独立于 pytest 套件 |

分类边界：**plans 是「打算做什么」，issues 是「发现了什么」。** 一份文档若既提出问题又给出完整实施方案，看它的主要用途 —— 是被当作施工依据（plans），还是被当作待查证据（issues）。

运行时行为的权威来源是代码和 `tests/`（882 passed），不是本目录。文档里的行号会腐化。
