# issues — 已知问题记录

开发过程中发现、但**不属于当次任务主线**的问题。放这里而不是直接修，通常是三种情况：

- 影响面超出当前任务范围，就地修会让改动失焦
- 需要产品决策，不是纯技术选择
- 已确诊但优先级不足，先留证据避免将来重新排查

每份文档应当写清：**状态**（未修复 / 部分缓解 / 已过期）、**发现时间与分支**、**复现或核实方式**、**若要修的建议路径**、以及**不建议做的事**。最后一项常被省略，但它防止后人踩同一个坑。
