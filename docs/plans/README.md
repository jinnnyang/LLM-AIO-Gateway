# plans — 开发规划与评审记录

历史上的功能规划、设计方案、以及围绕它们的评审往来。这里的文档**记录当时的判断**，不随实现漂移而回写 —— 想知道代码现在怎么跑的，读代码和测试；想知道当初为什么这么定，读这里。

一个例外：设计方案本身会维护「实现期偏离」章节，因为它是被反复查阅的权威口径，让它和实现脱节的代价高于保持历史纯净的收益。评审意见类文档只在头部加批注指向该章节，不就地改写结论 —— 改写会让评审历史失真。
